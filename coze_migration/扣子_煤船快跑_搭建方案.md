# 「煤船快跑」扣子(Coze)工作流搭建方案（全量迁移）

> 本文档把原 Streamlit 应用「煤船快跑——火电厂燃料调运管理智能体」完整迁移到扣子平台。
> 配合同目录文件使用：
> - `coze_db_schema.md`：三张数据库表字段定义
> - `coze_prompts.md`：人设与四个大模型节点的提示词
> - `coze_code_nodes/*.py`：可直接粘贴进「代码节点」的 Python 脚本（仅标准库）

---

## 0. 架构总览

```
用户自然语言
   └─ 煤船快跑 智能体（人设 + 快捷指令）
        ├─ 智能问答   → AI问答工作流
        ├─ 调运录入   → 调运录入工作流（单条 / 批量导入）
        ├─ 库存管理   → 库存管理工作流
        └─ 预警中心   → 预警中心工作流
```

- **数据**：扣子数据库，3 张表 `shipment_ledger` / `inventory_simple` / `inventory_txn`
- **计算**：代码节点（移植自 `business/*.py`、`ai/qa.py`）
- **语义**：大模型节点（意图识别、字段抽取、通用问答）
- **展示**：卡片节点（表格 / 指标 / 预警列表）

---

## 1. 准备工作

1. 打开 https://www.coze.cn 并登录。
2. 进入「个人空间 → 创建智能体」，名称填 **煤船快跑**，简介填「火电厂燃料调运管理智能体 ⛴」。
3. 在「人设与回复逻辑」粘贴 `coze_prompts.md` 的「一、智能体人设」。
4. 配置「模型」：默认「豆包」即可；若想用 DeepSeek，在模型下拉选 DeepSeek（无需自管 Key）。
5. 左侧切到「数据库」，按 `coze_db_schema.md` 建 3 张表。

> 提示：扣子代码节点**只能用 Python 标准库**，不能 import pandas/openpyxl/sqlite3。所有 DB 读写都通过「数据库节点」完成，代码节点只接收变量、输出变量。

---

## 2. 建库（数据库节点）

按 `coze_db_schema.md` 新建 3 张表，`id` 由平台自动生成。要点：
- 日期字段选「日期」，数量/价格/热值选「数字」，其余「文本」。
- `status` 文本，枚举值 `已下单,计划`；`calorific_class` 文本，枚举值 `低卡,中卡,高卡`。
- `inventory_simple.shipment_id` 与 `inventory_txn.shipment_id` 用于关联 `shipment_ledger`。

---

## 3. 工作流一：AI问答工作流

**开始节点**：输入 `query`（文本，必填，引用 `{{query}}`，来自用户问题）。

**节点1 大模型（意图识别）**：粘贴 `coze_prompts.md`「二」，输入 `{{query}}`，输出变量 `intent` / `date_str` / `grade` / `need_detail`（JSON 模式）。

**节点2 选择器（Selector）**：按 `intent` 分支
- `库存查询 / 到港查询 / 在途查询 / 逾期查询 / 热值分类 / 运单查询` → 走「精确路径」
- `通用` → 走「通用路径」

### 精确路径
- **数据库节点（查询 shipment_ledger）**：查询全部（或按 `grade`/`keyword` 过滤），输出 `shipments`。
- **代码节点（query.py）**：输入 `rows={{shipments}}`、`query_date={{date_str}}`、`grade={{grade}}`。把 `coze_code_nodes/query.py` 整文件粘贴，入口 `main`。输出 `result`（含 effective_inventory / arrived_qty / in_transit_qty / delay_count 等）。
- **卡片节点（结果卡片）**：用以下模板渲染（见第 7 节模板 A）。
- **结束节点**：输出卡片变量。

### 通用路径
- **数据库节点（查询 shipment_ledger + inventory_simple）**：输出 `shipments`、`inventory`。
- **代码节点（qa.py）**：输入 `question={{query}}`，输出 `context` 用 `build_context` 拼装（若需，把 `main` 改为调用 `build_context(shipments, inventory)` 后返回；或在代码节点内直接拼）。简单做法：再加一个代码节点传入 `shipments`/`inventory` 调 `build_context`，输出 `context`。
- **大模型节点（通用问答）**：粘贴 `coze_prompts.md`「三」，输入 `{{query}}` + `{{context}}`，输出回答文本。
- **结束节点**：输出回答文本。

---

## 4. 工作流二：调运录入工作流（单条 + 批量导入）

**开始节点**：输入 `text`（文本，用户口语或 CSV 文本）。

**节点1 选择器**：判断 `text` 是否为 CSV（含「船名,」或换行含逗号表头）→ 批量；否则单条。

### 单条录入
- **大模型节点（字段抽取）**：粘贴 `coze_prompts.md`「四」，输入 `{{text}}`，输出 `fields`（JSON）。
- **代码节点（classify.py）**：把单条 `fields` 包成列表传入 `rows`，输出带 `calorific_class`+`status` 的行。入口 `main`。
- **数据库节点（新增 shipment_ledger）**：写入该行。
- **卡片/结束**：返回「已录入：船名 X，热值分类 Y，状态 Z」。

### 批量导入
- **代码节点（csv_io.py）**：输入 `csv_text={{text}}`，输出 `rows`。粘贴 `coze_code_nodes/csv_io.py`，入口 `main`。
- **代码节点（classify.py）**：输入上一步 `rows`，输出归类后 `rows`。
- **数据库节点（查询 shipment_ledger）**：读取已有数据，输出 `existing`（用于去重）。
- **代码节点（validate.py）**：输入 `rows={{分类后rows}}`、`existing={{existing}}`，输出 `valid_rows` / `errors` / `dup_rows`。粘贴 `coze_code_nodes/validate.py`，入口 `main`。
- **数据库节点（批量新增 shipment_ledger）**：写入 `valid_rows`。
- **卡片节点（导入结果）**：展示成功条数 + 错误/重复明细（模板 B）。
- **结束节点**：输出结果。

> 批量写入：扣子「数据库节点」支持「批量添加」，把 `valid_rows`（数组）直接连到该输入即可。

## 5. 工作流三：库存管理工作流

**开始节点**：输入 `text`（如「同步库存」「XX船入库5万吨」「高卡煤库存统计」）。

**节点1 大模型（操作路由）**：粘贴 `coze_prompts.md`「五」，输出 `action` ∈ {sync, in, out, set_param, stats, list}。

**节点2 选择器**：按 `action` 分支。

- **sync**：数据库节点查 `shipments` → 代码节点 `inventory.py`（`action="sync"`）输出 `sync_ids` → 数据库节点批量新增 `inventory_simple`（shipment_id + 运单数量）→ 卡片「已同步 N 条」。
- **in / out**：数据库节点查该 `shipment_id` 的 `inventory_simple` 得 `quantity` → 代码节点 `inventory.py`（`action="txn"`，`quantity`/`qty`/`txn_type`）算 `new_quantity` → 数据库节点更新库存 + 新增 `inventory_txn` 记录 → 卡片回显。
- **set_param**：数据库节点更新 `safety_stock` / `expiry_date`。
- **stats**：数据库节点 JOIN 查询 `inventory_simple` + `shipment_ledger`（取 calorific_value）→ 代码节点 `inventory.py`（`action="stats"`）输出 `stats`（按低/中/高卡汇总）→ 卡片（模板 C）。
- **list**：数据库节点查全部库存 → 卡片列表。

---

## 6. 工作流四：预警中心工作流

**开始节点**：无输入（或 `text` 触发）。

- **数据库节点**：查询 `shipment_ledger` → `shipments`；查询 `inventory_simple` → `inventory`。
- **代码节点（alerts.py）**：输入 `shipments`、`inventory`，粘贴 `coze_code_nodes/alerts.py`，入口 `main`，输出 `delay` / `others` / `total_count` 等。
- **卡片节点（预警面板）**：展示三类预警统计 + 明细（模板 D）。逾期=error 红，低库存/效期=warning 黄。
- **结束节点**：输出卡片。

---

## 7. 卡片模板

> 卡片节点用 `{{变量.字段}}` 渲染。下表为模板示例，按实际变量名调整。

### 模板 A：查询结果（库存/到港/在途/逾期）
```
📊 {{result.query_date}} 调运简报（等级：{{result.grade}}）
• 有效库存：{{result.effective_inventory}} 万吨（{{result.effective_count}} 船）
• 当日到港：{{result.arrived_qty}} 万吨
• 当日计划到港：{{result.planned_qty}} 万吨
• 在途：{{result.in_transit_qty}} 万吨
• 总运输量：{{result.total_transport}} 万吨
• 逾期：{{result.delay_count}} 船
{% if result.delay_count > 0 %}
逾期明细：
{% for d in result.delay_shipments %}- {{d.vessel_name}} 调整到港 {{d.adjusted_arrival_date}}（{{d.quantity}}万吨）
{% endfor %}{% endif %}
```

### 模板 B：批量导入结果
```
✅ 导入完成：成功 {{valid_count}} 条
{% if error_count > 0 %}⚠️ 跳过 {{error_count}} 条（校验/重复）：
{% for e in errors %}- 第{{e.index}}行 {{e.vessel_name}}：{{e.messages}}
{% endfor %}{% endif %}
```

### 模板 C：热值分类库存
```
📦 库存热值分类（总 {{stats.高卡.qty|default:0}}+{{stats.中卡.qty|default:0}}+{{stats.低卡.qty|default:0}} 万吨）
• 高卡：{{stats.高卡.qty}} 万吨（{{stats.高卡.count}} 船）
• 中卡：{{stats.中卡.qty}} 万吨（{{stats.中卡.count}} 船）
• 低卡：{{stats.低卡.qty}} 万吨（{{stats.低卡.count}} 船）
```

### 模板 D：预警面板
```
🚨 预警中心（共 {{total_count}} 条）
运输逾期：{{delay_count}} 条 | 低库存/效期：{{other_count}} 条
{% for w in all %}[{{w.level}}] {{w.type}}：{{w.message}}
{% endfor %}
```

## 8. 测试与发布

1. 在每条工作流的「预览」中跑通：录入 1 条 → 同步库存 → 看预警 → 问答「今天库存多少」。
2. 智能体对话测试：发「录入一条运单：神华轮，供货方神华，计划到港2026-08-01，热值4800，数量12万吨」验证自动归类与分类；发「8月15日在港多少」验证精确查询。
3. 顶栏「发布」→ 勾选渠道（扣子商店 / 飞书 / 微信等）→ 发布。
4. 发布后，把智能体链接发给测试人员即可对话使用。

---

## 9. 灌入测试数据（你来执行）

1. 准备好测试 Excel，表头用 `coze_code_nodes/csv_io.py` 的 19 个中文列名（含「状态」）。
2. 把 Excel 另存为 **CSV（UTF-8）**，复制全部内容。
3. 在智能体里说：「导入运单」并粘贴 CSV 文本 → 走「调运录入工作流 / 批量导入」自动归类、校验、去重并写库。
4. 或在扣子「数据库 → 数据管理」里直接逐条添加（调试期更直观）。
5. 灌完后说「同步库存」「看看预警」，验证全链路。

## 10. 与原 Streamlit 的对应关系

| 原模块 | 扣子实现 |
|---|---|
| pages/_transport_page.py（录入/导入） | 调运录入工作流 + csv_io/classify/validate 代码节点 |
| business/transport.py（分类/查询/逾期） | query.py / classify.py / alerts.py |
| pages/2_库存.py + business/inventory.py | 库存管理工作流 + inventory.py |
| pages/3_预警.py | 预警中心工作流 + alerts.py |
| ai/qa.py + pages/4_问答.py | AI问答工作流 + qa.py + 大模型节点 |
| db/init_db.py + data_service.py | 扣子数据库 3 表 + 数据库节点 |

> 本迁移不修改原 Streamlit 项目源码；所有扣子配置与脚本均在本 `coze_migration/` 目录。
